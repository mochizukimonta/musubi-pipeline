# セキュリティ設計

P2P同期を使ったチーム制作環境の脅威モデルと、それに対してこのアドオンが
何をしているかの文書です。

対象: Musubi Pipeline アドオン + P2P同期ツール(Syncthing / Resilio Sync)による
チーム制作環境(複数端末で同一プロジェクトフォルダを同期)。

> **脆弱性を見つけた場合の報告手順は [SECURITY.md](../../SECURITY.md) にあります。**
> 公開 Issue には書かないでください。

## 結論(要約)

1. **P2P同期を自前実装しない**ことが最大のセキュリティ対策。暗号・鍵交換・
   NAT越えを独自実装すると脆弱性がほぼ確実に入る。同期プロトコルは
   **Syncthing**(オープンソース・TLS 1.3・デバイスID認証)に委任し、
   アドオンはそのセットアップ自動化と「検証役」に徹する。
   アドオン自身の外部通信は次の2つに限定される:
   - 公式GitHubリリースからの syncthing.exe 取得(初回のみ・下記の検証付き)
   - 127.0.0.1 のローカルREST API(Syncthingの制御)
2. **同期フォルダは「他人が書き込めるフォルダ」として扱う。** そこから読む
   ファイル・JSON・ファイル名はすべて信頼できない入力として検証する。
3. Blender固有の最重要リスクは **.blend への Python 埋め込み**。
   「Auto Run Python Scripts」を全端末で必ず無効化する(アドオンの監査が検出)。

---

## 脅威モデルと対策

### 0. 同期ソフト自体の入手経路(サプライチェーン)

アドオンが自動ダウンロードする syncthing.exe は:

- 取得元を `github.com` / `api.github.com` / `objects.githubusercontent.com`
  へのHTTPSに**ホワイトリスト固定**(それ以外のURLは拒否)
- 同一リリースの `sha256sum.txt.asc` に記載されたハッシュと
  **SHA-256照合してから展開**(不一致なら即中止)
- zip展開時はパス検証(Zip Slip対策)を行い、syncthing.exe のみ取り出す
- 導入したバージョンとハッシュを `install.json` に記録(監査証跡)

信頼の起点はGitHubへのTLSとSyncthingプロジェクトのリリース運用である。
より厳格にする場合は、管理者が検証済みバイナリを
`%LOCALAPPDATA%\musubi_pipeline\syncthing\bin\syncthing.exe` に事前配置すれば
ダウンロードは行われない。

### 1. 転送路の盗聴・改ざん

| | Syncthing | Resilio Sync |
|---|---|---|
| 暗号化 | TLS 1.3、相互認証 | AES-128、独自プロトコル |
| 認証 | デバイスID(証明書のSHA-256)を手動承認 | フォルダ共有キー(シークレット) |
| ソース | オープンソース(監査可能) | クローズド |

- どちらも転送は暗号化される。**平文で流れることはない**。
  インターネット越し(リレー経由含む)でも端末間TLSのまま運ばれ、
  リレーサーバは中身を読めない。
- 本アドオンはSyncthingを採用・自動セットアップする。デバイス単位の
  承認制で、**新メンバーの参加は必ずリーダーの「承認」操作を要求**する
  (アドオンは自動承認しない)。承認前に**デバイスIDを口頭・ビデオ通話等の
  別経路で照合**すること。デバイスIDは公開情報扱いで、漏れても
  秘密鍵がなければなりすませない(Resilioの共有キーより安全)。
- **共有範囲の限定**: 相手に見えるのは明示的に共有した1フォルダのみ。
  ピア登録時に `autoAcceptFolders=false` を明示設定しており、相手が
  別フォルダを共有提案してもパネルに警告表示されるだけで、
  こちらの操作なしには何も同期されない。アドオン管理外の共有フォルダが
  設定に存在する場合もステータス診断が赤字で警告する。
- **ライフサイクルの可視化**: 稼働中はパネルにPID・稼働時間・接続ピア・
  転送ログを常時表示(数秒ごと自動更新)。Blender終了時はatexitで
  自動停止する(ヘッドレステストで検証済み)。クラッシュ時など万一
  残留した場合もパネルの「稼働中」表示で気づける。
- Resilio Sync を使う場合はキーを平文共有しない(1Password等で受け渡し)。
  照合リスト検証・ロック等のアドオン機能は同期ツールを問わず動作する。

### 2. 中継サーバ・トラッカーへの露出

- 両ツールとも、NAT越えのために外部のリレー/トラッカーサーバを使う。
  中継データは暗号化済みだが、メタデータ(IP、通信量)は露出する。
- **推奨**: 全端末を Tailscale 等のWireGuard系VPNで結び、パネルの
  「**LAN/VPN内のみ**」を有効にして同期セットアップを実行する
  (リレー・グローバル探索・NAT越えを無効化し、外部サーバへの露出がゼロになる)。

### 3. フォルダポイズニング(悪意ある/事故的なファイル混入)

P2P共有フォルダは「チーム全員が書き込めるフォルダ」= 1台の端末の侵害が
全端末に伝播する経路になる。

- **`.blend` 内蔵Pythonの自動実行が最大の攻撃面**。ドライバー式や
  登録済みテキストブロックは開くだけで実行され得る。
  → 全端末で `設定 > Save & Load > Auto Run Python Scripts` を**無効**。
  → 本アドオンの「セキュリティ監査」が有効になっていると CRITICAL 警告を出す。
- 実行ファイル(.exe .py .bat .ps1 等)の混入をアドオンが走査して警告する。
  成果物(.blend/画像/動画)以外は同期フォルダに置かない運用を徹底。
- Windows Defender等のリアルタイム保護を同期フォルダで**除外しない**。

### 4. パストラバーサル・シンボリックリンク

- アドオンのすべてのファイル操作は `os.path.realpath` で解決後に
  プロジェクトルート配下であることを検証(`core.safe_path`)。
- ルート外を指すシンボリックリンクは監査で CRITICAL として検出
  (同期ツール経由でリンクが混入し、ルート外のファイルを読み書き
  させられる攻撃の防止)。
- ファイル名・フォルダ名は正規表現ホワイトリスト
  (`scene\d+`, `c\d+`, `char|bg|prop`)のみ許可。

### 5. 同時編集・競合によるデータ消失

P2Pにはロック機構がないため、同じ .blend を2人が同時に編集すると
片方が競合コピー(`.sync-conflict-*` / `*.Conflict*`)に退避され、
気づかないと作業が失われる。

- アドオンの**アドバイザリロック**(`cXX.blend.lock`、ロック自体も同期される)
  で「誰がどのカットを編集中か」を全端末で共有。他端末のロック中は保存を拒否。
- 競合ファイルの発生を監査・同期検証で検出して警告。
- **同期ツール側のバージョニングを必ず有効化**
  (Resilio: Archive / Syncthing: File Versioning「Staggered」推奨)。
  ランサムウェア・誤削除・誤上書きからの復旧手段になる。

### 6. 同期の「なりすまし完了」・サイレント破損

「同期された気がする」と「本当にバイト単位で一致している」は別物。

- 各端末が **SHA-256 同期照合リスト**(`.musubi/manifest_<host>.json`)を書き出し、
  他端末はそれとローカル実ファイルを突き合わせて
  **一致 / 未到達 / 差分 / 余剰** を検証できる(`同期状態を検証`ボタン)。
- SHA-256は暗号学的ハッシュなので、転送エラー・部分同期・改ざんを検出できる。

### 7. 秘密情報の取り扱い

- 同期フォルダ内(`.musubi/` 含む)には**秘密情報を一切置かない**設計。
  照合リストに含まれるのはホスト名・ユーザー名・ハッシュのみ。
- SyncthingのAPIキー・デバイス秘密鍵は各端末の
  `%LOCALAPPDATA%\musubi_pipeline\syncthing\home`(同期対象外)に置かれ、
  プロジェクトフォルダには書き出されない。REST APIは127.0.0.1のみで
  待ち受け、アドオンはループバック以外への公開を拒否する。
- 本アドオンは設定をBlenderのシーンプロパティ(パスのみ)に持ち、
  認証情報を保存しない。

### 8. メンバーの離脱・端末紛失

- Syncthing: 全端末から当該デバイスIDを削除(即時遮断)。
- Resilio: **フォルダキーの再発行(全員再共有)が必要**。キーを知る者は
  永久に参加できてしまうため、離脱時の運用コストはResilioの方が高い。
- 端末側でディスク暗号化(BitLocker)を有効にしておく。

## 運用チェックリスト(全端末)

- [ ] Blender: Auto Run Python Scripts = 無効(監査で確認)
- [ ] 同期ツールのバージョニング有効(Archive / Staggered)
- [ ] 可能なら Tailscale 等でLAN化し、リレー・グローバル探索を無効化
- [ ] 共有キー/デバイス承認は安全な経路で受け渡し・照合
- [ ] OSのリアルタイムウイルス保護を同期フォルダで有効のまま維持
- [ ] ディスク暗号化(BitLocker)有効
- [ ] 週1回程度「同期照合リストを作成→同期状態を検証」「セキュリティ監査」を実行
