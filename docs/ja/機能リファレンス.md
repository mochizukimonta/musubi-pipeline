## フォルダ構造

「フォルダ構造を作成」はテンプレート選択式です。最も業務に近いものを選びます。

| テンプレート | 作られるもの | 向いている現場 |
|---|---|---|
| **映像制作(シーン・カット)** | assets(+texture)・scenes/scene01〜03・output・.musubi | カット管理・進捗ボード・リールまで使う |
| **アセット制作(持ち寄り・リンク用)** | assets(+texture)・ref・output・.musubi | モデルを分担制作し、他プロジェクトからリンクして使う |
| **最小構成(自由なフォルダ構成)** | output・.musubi のみ | フォルダ構成をチーム独自に決めたい |

**どのテンプレートでも全機能が使えます。** 映像制作向けの機能を後から
使いたくなっても、カット管理を使えば `scenes/` は必要時に自動生成されます。

映像制作テンプレートの構造:

```
<プロジェクトルート>/          ← P2P同期の対象フォルダ
├── assets/
│   ├── char/                  ← キャラクターモデル
│   │   └── texture/
│   ├── bg/                    ← 背景モデル
│   │   └── texture/
│   └── prop/                  ← 小物モデル
│       └── texture/
├── scenes/
│   └── scene01/
│       ├── c01.blend          ← シーン01 カット01
│       ├── c01.blend.lock     ← 編集中ロック(自動生成・同期される)
│       └── c02.blend
├── output/
│   └── scene01/
│       ├── c01.001.mp4        ← バージョン付き最終出力
│       └── c01.002.mp4
└── .musubi/                   ← 管理フォルダ
    ├── manifest_<端末名>.json  ← 同期照合リスト(SHA-256)
    ├── board.html              ← 進捗ボードのHTML版
    ├── status/                 ← 進捗ステータス(1カット=1ファイル)
    ├── reviews/                ← バージョン紐付けレビューコメント
    └── versions/               ← バージョン履歴
```

命名規則は正規表現で固定されています(`scene01`〜`scene999` /
`c01`〜`c999` / `c01.001.mp4`)。この形から外れたファイルは
カット管理の対象になりません。

## チーム同期

「チーム同期」ボックスは**今やるべき操作を1つだけ大きく表示**します。
基本はそれを押していけば繋がります(デバイスIDの手動貼り付けなどは
「詳細」に折りたたまれています)。

セットアップ操作の直後だけ、接続が成立するまで(最長5分)状態表示が
自動更新されます。成立後は通常のイベント駆動に戻ります。

### 立ち上げる人(最初に1回)

1. 「ルート」にプロジェクトフォルダを指定 → **フォルダ構造を作成**
2. 「同期ID」を決める(例: `musubi-mymovie`)
3. **① 同期を始める** — 初回は Syncthing を自動ダウンロード(SHA-256検証つき)。
   ファイアウォールのダイアログが出たら許可します
4. **② 招待ファイルを送る** — 招待ファイルが書き出されるので、
   チャット等でメンバーへ渡します(中身はデバイスID等の公開情報のみ)
5. メンバーから申請が来ると赤いボタンが出ます →
   **▶ 参加申請を承認する**。**承認前に、相手のデバイスIDを通話等の
   別経路で本人確認してください**
6. 「✓ 同期OK」が出たら完了

### 参加する人(最初に1回)

1. アドオンをインストールし、「ルート」に空のフォルダを指定
2. **① 招待ファイルで参加** — もらった招待ファイルを選ぶだけ。
   同期IDの設定・Syncthing の起動・接続申請まで自動です
3. 「リーダーの承認を待っています」→ 承認されると自動でファイルが
   流れ込み、他のメンバーとも自動接続されます(ペアリングは1回だけ)
4. **「✓ 同期OK — 作業を始めてください」**が出たら完了

### 手動で Syncthing を用意する

社内プロキシやアンチウイルスが HTTPS 通信を傍受している環境では、
自動ダウンロードが証明書エラー(`CERTIFICATE_VERIFY_FAILED`)で失敗する
ことがあります。手動で用意できます(セキュリティ上もむしろ確実です)。

1. ブラウザで <https://github.com/syncthing/syncthing/releases> を開く
2. 最新版の `syncthing-windows-amd64-vX.Y.Z.zip` を展開
3. 中の `syncthing.exe` を次の場所に置く(フォルダがなければ作成):
   `%LOCALAPPDATA%\musubi_pipeline\syncthing\bin\syncthing.exe`
4. Blender で「同期セットアップ / 起動」を押す
   → 既に実行ファイルがあるのでダウンロードはスキップされます

管理者が検証済みの exe を各PCのこの場所に配っておく運用も可能です。

### 同期状態の見方

状態表示は「ファイルを開いた時 / 保存した時 / 更新ボタンを押した時」だけ
バックグラウンドで取得されます。**常駐タイマー・常時ポーリングはなく、
作業中の Blender に負荷をかけません**(同期そのものは Syncthing が
別プロセスで継続します)。

ファイルを開いた時に「停止中」や「同期中 残り○MB」が出ていたら、
**同期完了を待ってから作業を始めてください。**

パネルに常時表示される情報:

- **稼働中 PID xxxx** — Syncthing プロセスが動いている証明。
  「停止中 — 同期は行われていません」なら同期は動いていません
- **ピアごとの接続状態** — 誰と接続できているか(IPアドレス付き)
- **フォルダ状態** — 待機中(同期済み)/ 同期中(残りMB)/ 走査中
- **問題診断(赤字)** — 同期されない理由を具体的に表示します:
  - 「同期IDの不一致」→ 相手と同期IDが揃っていません。どちらかを合わせます
  - 「ピア未登録」「どのピアにも接続できていません」「承認待ち○件」
- **直近の同期ログ** — どのファイルをいつ受信したか

### 共有中のプロジェクト一覧

この端末が同期しているプロジェクトを**1プロジェクト1枠**で並べます。
複数の現場に参加している場合でも、どれがどこにあり、いま同期できているかを
まとめて見渡せます。

各枠は「状態のドット + 同期ID」「フォルダの場所」「状態 · 相手」の3行です。
先頭のドットが状態を表します。

| ドット | 意味 |
|---|---|
| 緑 | 待機中(同期済み) |
| 青 | 同期中(転送しています) |
| 黄 | 一時停止中 |
| 橙 | 同期できないファイルがある |
| 赤 | 誰とも共有していない = **同期されていません** |

現在作業しているプロジェクトは先頭に固定され、「現在」と表示されます。
**他のプロジェクトが並んでいること自体は異常ではありません**(意図して
複数に参加している場合があるため)。赤くなるのは実害があるものだけです。

各プロジェクトには2つの操作があります。

- **一時停止 / 再開** — そのプロジェクトの同期だけを止めます。
  **共有設定は壊れないので、いつでもボタン1つで戻せます。**
  「いまはこのプロジェクトだけ同期したい」というときはこちらを使ってください
- **解除** — 共有フォルダの登録そのものを外します(確認あり)。
  ディスク上のファイルは消えませんが、**戻すには招待からやり直しが必要**です

### ライフサイクル

- Syncthing は「同期セットアップ / 起動」を押したときだけ起動します
- **Blender を終了すると自動で停止します。** 「同期を停止」で手動停止も可能です
- 稼働中はパネルに PID と稼働時間が出続けるので、動いているかで迷いません

### インターネット越しの同期

そのまま LAN 外でも同期できます。「LAN/VPN内のみ」をオフ(既定)に
しておくと、Syncthing のグローバル探索でお互いを見つけ、NAT越えできない
場合は公式リレー経由で接続します。**通信は端末間で TLS 暗号化された
ままで、リレーは中身を読めません。**

あまり知らない相手と作業する場合の設計上の保証:

- 相手に見えるのは**共有した1フォルダの中身だけ**です。Syncthing は
  フォルダ単位の明示共有で、相手がこちらのPCの他のフォルダに触れる手段は
  ありません
- 相手が別のフォルダを共有してきても**自動受諾しません**。パネルに赤字で
  提示されるだけで、こちらが操作しない限り何も起きません
- 参加には必ずリーダーの「承認」操作が必要です

より厳格にしたい場合は、全端末を Tailscale 等の VPN で結び
「LAN/VPN内のみ」を有効にしてください(リレー・グローバル探索を無効化し、
外部サーバへの露出がゼロになります)。

## カット作業

**モデラー** — 成果物を `assets/char|bg|prop` に保存するだけです(同期は自動)。

**アニメーター**

1. シーン番号・カット番号を入力し **カットとして保存**
   → `scenes/sceneXX/cYY.blend` に保存され、同時に**ロックを取得**します。
   他の人が編集中のカットは保存できません(誰が編集中か表示されます)
2. 以後はふつうに `Ctrl+S` で保存すれば、履歴・ロック・進捗が自動更新されます
3. 最終チェック後 **最終出力をレンダリング**
   → `output/sceneXX/cYY.NNN.mp4` にバージョン番号自動採番で出力されます
4. 作業が終わったら**閉じるだけ**です(ロックは自動で返ります)

ロックは `.blend` を開いた時点で自動取得され、閉じるか Blender を終了すると
自動で返されます。他の人がロック中のファイルを開くと、開いた瞬間に警告
ダイアログが出て、パネル最上部にも赤い警告が残り続けます。

**ロックを解放**ボタンは、この自動解放の補助です。ふだんは押す必要がありません。
Blender を開いたままロックだけ先に手放したいときや、強制終了などで自分の
ロックが残ってしまったときに、シーン/カット番号を指定して押します。
**他の人のロックは剥がせません**(自分の端末が取得したロックだけが対象です)。

### 放置ロックの解除(相手が戻ってこないとき)

Blender が強制終了した、PCが故障した、担当者が長期不在——こうした理由で
ロックが残り続けることがあります。12時間以上経過したロックは「放置ロック」
として監査が警告します。

放置ロックは、そのカットを**開いたときに出る赤い警告の中に現れる
「放置ロックを解除」ボタン**から引き継げます。押すと確認ダイアログが出て、
誰のロックを何時間ぶんに渡って解除するのかが表示されます。チェックを入れて
実行すると、ロックが外れて**そのまま自分のロックに置き換わります**。

- **12時間を過ぎていないロックは、このボタンでも解除できません。**
  作業中の相手からロックを奪えないようにするためです
- ボタンは放置ロックのときだけ表示されます
- 読み取れない壊れたロックファイルも、この操作で片付けられます

**解除する前に、可能なかぎり本人に連絡してください。**本人がまだ作業していた
場合、その作業は取り込まれずに失われます。ダイアログのチェックはそのための
確認です。

## バージョン管理

カットにもアセットにも効きます(プロジェクト配下の `.blend` すべて)。

- **スナップショットを保存** — コメント付きで履歴へ退避します。
  内容が前回と同じなら世代は増えません(SHA-256 による重複排除)
- 一覧には「日付 作者 コメント」で**全端末分**の履歴が新しい順に並びます
  (履歴も同期されるので、他の人の保存時点にも戻せます)
- **復元(⟲ボタン)** — 選択した世代に巻き戻します。復元前の状態も
  自動で履歴に退避されるので、失敗しても必ず戻れます。
  他端末がロック中のファイルは復元できません
- **古い履歴を整理** — 保持世代数(既定20)を超えた古い世代を削除します。
  「このファイル」と「全体」の2つのボタンがあります

`Ctrl+S` による自動履歴は、**コメント無しの場合10分ごとにまとめて**
記録されます(短時間に何度保存しても世代が無限に増えないようにするため)。
**コメントを書いた保存は必ずその場で記録されます。** ファイル自体は
常に最新なので、「保存したのに履歴が増えていない」ように見えたら
パネルの「最終保存」の時刻を見てください。

### 履歴の容量対策

重い `.blend` だと履歴が全員のディスクを圧迫します。3つの対策があります
(プリファレンス、またはバージョン管理パネルから)。

- **このPCだけに保存(同期しない)** — 履歴を自分のPCだけに留めます。
  既にある履歴は消えません(非破壊)。オフに戻すとまた全員と共有し直します。
  **この設定は端末ごとに個別**です(`.stignore` は端末間で同期されないため)
- **合計サイズ上限(GB)** — 超えたら、各ファイルの最新世代は必ず残しつつ
  古い世代から自動削除します。保存後のバックグラウンド処理で行うので
  保存は遅くなりません
- **全カットの履歴を一括整理** — プロジェクト内の全ファイルを
  保持世代数までまとめて整理します(削除も同期で全員に反映されます)

## 進行ボード

シーン×カットの全タスクを一覧し、チーム全員で共有します(同期で全端末に反映)。

- 各行: `s01/c01  状態  担当  v003  [編集中:○○]  指示メモ`
- ステータス: 未着手 / 作業中 / レビュー待ち / リテイク / 承認済み / オミット
- **自動遷移**: 「カットとして保存」→ 作業中(担当が空なら保存者に)、
  「最終出力をレンダリング」→ レビュー待ち。手動変更は「状態変更」メニュー
- 「カットを予定に追加」で `.blend` 作成前のカットもボードに載せられます
  (絵コンテ段階で全カットを並べて進捗率を管理できます)
- サマリ行に「承認 n/全体 (%)」と状態別の件数を常時表示
  (オミットは分母から除外)

**監督・チェック担当の使い方**: レビュー待ちで絞り込み → mp4 を確認 →
OK なら「状態変更 → 承認済み」、NG なら「リテイク」+「指示」ボタンで
内容を記入します(担当者は次の保存で自動的に作業中へ戻ります)。

作業をせず進捗確認と指示が中心の人は、プリファレンスで役割を
**「レビュアー」**にするとパネルが必要なものだけになります。
カットを「開く」で中を見ることもできますが、**開いている間は作業者と
同じロックが付く**ので、見終わったら閉じてください。

## レビューコメント

「どの mp4 に対する指示か」を明確にしたレビューを残せます。

- ボードでカットを選択 → **コメント追加** — 対象バージョン(既定は最新)、
  フレーム番号(任意)、判定、本文を入力
- 判定がステータスに連動します:
  - **リテイク** → カットがリテイクになり、指示メモにも本文が入ります
  - **承認** → カットが承認済みになります
  - **コメントのみ** → ステータスは変わりません
- 一覧は `v005 f12 [リテイク] 日付 作者: 本文` の形式です

コメントは**追記のみで編集・削除できません**。不変ログを前提にすることで
同時書き込みの衝突をゼロにしています。取り消したい場合は
「取り消しコメントを追加する」形で表現してください。

## HTMLボード

**HTMLボードを書き出す** で `.musubi/board.html` を生成します
(ステータス変更・レビュー追加時にも自動更新)。制作進行・プロデューサーは
**ブラウザで開くだけ**で以下が見られます。

- 全体進捗バーとステータス別の件数
- シーン別のカット一覧(状態・担当・編集中・指示メモ・最終更新者)
- **最新出力 mp4 への直リンク**(クリックでそのまま再生)
- カットごとのレビューコメント履歴(折りたたみ)
- プロジェクト仕様(レンダープロファイル)の対照表

外部リソースを読まない自己完結ファイルなのでオフラインでも開けます。
メモ・コメントはすべてエスケープ済みです(HTML注入対策)。

**board.html は同期されません。** 各端末でローカル生成したものを開く運用です
(HTML を同期で配ると、悪意あるピアが差し替えたものを他の人のブラウザで
開かせる経路になるため)。

## プロジェクト仕様

`.musubi/spec.json` として管理され、同期で全端末へ配布されます。
board.html にも掲載されるので、Blender を持たない人もブラウザで確認できます。

### ① レンダー仕様テンプレート

「本番」と「仮(プレビュー)」の2プロファイルを持ちます。

| 項目例 | 本番(既定) | 仮(既定) |
|---|---|---|
| エンジン / サンプル数 | Cycles / 128 | Cycles / 16 |
| 出力形式 | OpenEXR マルチレイヤー連番 16bit | mp4(H.264) |
| 解像度 | 1920×1080 100% | 同 50% |
| ピクセルフィルター幅 | 0.01(実質0・輪郭シャープ) | 1.5 |
| フィルム透過 | ✓(コンポジット前提) | ─ |
| パス | 統合・Z・放射(Emit) | 統合のみ |
| Cryptomatte | オブジェクト✓ マテリアル✓ | ─ |
| fps | 24 | 24 |

- **本番を適用 / 仮を適用** — ワンクリックでシーンに一括反映します
  (仮でチェック用 mp4 を出し、納品前に本番へ切替、という運用)
- **シーンから仕様に取り込み** — 手入力は不要です。普通の Blender UI で
  シーンを整えて押せば、その設定がそのままチームの仕様になります
- 管理項目は約22項目。追加は `render_profiles.py` の `SETTINGS` に
  1行足すだけで、取り込み・適用・差分・品質チェック・HTMLボードの
  すべてに反映されます

### ② 備考(自由メモ・1欄)

映像尺・納品先などのメモ用です。

### 生きたチェックリストとして機能する

「本番の仕様値」「仮の仕様値」を開くと、Blender の実際の UI 配置
(レンダープロパティ / フィルム / 出力プロパティ / カラーマネジメント /
View Layer > パス)でグループ化された一覧が出ます。
**現在のシーンが仕様と違う項目はその場で赤く「≠ 現在値」と表示**されるので、
どこを直せばよいかが一目で分かります。

## 品質チェック

保存のたびに自動実行され、問題があるとパネルに**赤いアラート**で残ります
(保存は止めません — 気づいて自分で直す方式です)。

- スケール未適用(スケールにキーがあるものは除外)
- 命名規則違反(`Cube` / `Material.001` などデフォルト名のまま)
- テクスチャ: リンク切れ(CRITICAL)/ プロジェクト外参照(パック推奨)
- 不要データ(参照ゼロの孤立データブロック)
- リンク: リンク切れライブラリ(CRITICAL)/ 絶対パス(他端末で壊れる)/
  プロジェクト外へのリンク
- レンダー設定と仕様の整合(3段階判定: 本番と一致 / 仮のまま / 不一致)

修正は確認付きの明示ボタンのみです(**自動では何も変更しません**):
**選択**(問題オブジェクトを選択して手動修正)/ **パック** /
**不要データ削除** / **相対パス化**。

`copybuffer.blend` がリンク切れとして出ることがありますが、これは Blender が
コピー&ペースト(`Ctrl+C`/`V`)に使う一時ファイルで、このアドオンとは
無関係です(パネルにもその説明が出ます)。

## アセット参照の管理

- カット保存時に「このカットがどの `.blend` をリンクしているか」を
  `.musubi/deps/` に自動記録します(全端末分が同期で集まります)
- **アセット使用状況** ボタンで
  「`hero.blend` ← `scene01/c01`, `scene01/c02`」のような逆引き一覧を
  表示します。アセット更新時の影響範囲がすぐ分かります
- リンク元が更新されると、パネルに黄色で「リンク元が更新されています」と
  出ます。**リンクを再読み込み** を押せば、ポーズやキーフレームを保持した
  まま最新のアセットに置き換わります(開き直しは不要です)

## デイリーズリール

**デイリーズリールを作成** — 各カットの最新出力 mp4 を1本に連結して
`output/reel/reel.NNN.mp4` に書き出します(バージョン自動採番)。

映像左下にカット名ラベル(`s01/c01 v005 [approved]`)を焼き込みます。
「承認済みカットのみ」オプションで納品確認用リールも作れます。

## 同期の担保と監査

定期的(週1回程度)に全員が実行することを想定した機能です。

1. **同期照合リストを作成** — 全ファイルの SHA-256(中身の指紋)を記録し、
   `.musubi/manifest_<端末名>.json` に書き出します
2. **同期状態を検証** — 他端末の照合リストと自分の実ファイルを突き合わせ、
   **完全一致 / 未到達 / 差分 / こちらのみ** を報告します。
   SHA-256 は暗号学的ハッシュなので、転送エラー・部分同期・改ざんを検出できます
3. **セキュリティ監査** — 以下を一括チェックします:
   - Blender の Python 自動実行(Auto Run)が無効か ← **最重要**
   - 同期フォルダへの実行可能ファイル混入
   - 同期競合ファイル(`.sync-conflict-*`)の有無 = データ消失の兆候
   - 放置されたロック(12時間以上。解除は
     [カット作業](#放置ロックの解除相手が戻ってこないとき)を参照)
   - プロジェクト外を指すシンボリックリンク
   - **端末間の環境不一致** — Blender のメジャーバージョンが端末間で違うと
     CRITICAL 警告(新しい版で保存した `.blend` を古い版で開くと壊れるため)。
     アドオンのバージョン違いは WARN

## パネルの色の意味

| 表示 | 意味 |
|---|---|
| **✓ 緑・チェック** | 正常。何もしなくてよい |
| **⚠ 黄色い三角** | 注意。すぐには困らないが把握しておく |
| **赤い文字** | 問題。書いてある指示に従って直す |

赤(CRITICAL)は乱発しない方針です。出たら実際に対処が必要です。

こまったら **「同期状態を更新」** を押してください。今の状態と
「次にやること」がパネルに表示されます。
